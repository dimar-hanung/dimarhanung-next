## When to Use

Changing anything under `pages/(home)/` or its copy in `locales/home/`: nav, hero, themes section, selected work, services, steps, contact form, "Beyond client work" or the footer. Writing or changing a home theme (see "Home themes" below). Also changing the Milky Way stack on `/challenges/ui-general`.

The home page is a freelance "hire me" page (freelance projects only: no full-time / role wording). Page order: `HomeNav` (sticky) → `SectionHero` (`#top`) → `SectionThemes` (`#themes`) → `SectionWork` (`#work`) → `SectionServices` (`#services`) → `SectionProcess` (`#process`) → `SectionContact` (`#contact`) → `SectionMore` ("Beyond client work") → `SectionFooter`, plus the phone-only contact bar in `index.vue`. Container everywhere: `mx-auto max-w-7xl px-5 sm:px-6`; section rhythm `py-(--section-y)` (72px, 100px from md). No color utilities (`bg-white`, `text-muted-600`, `dark:` …) in home markup: colors, fonts, radii, borders and shadows come from the theme contract in `pages/(home)/home-theme.css` (see "Home themes"). Shared classes `section-title`, `section-sub`, `btn-primary`, `btn-ghost`, `text-link` are defined there too.

## i18n (EN at `/`, ID at `/id`)

- No `@nuxtjs/i18n`: only the home page is translated, so `/id` is a second route record for `pages/(home)/index.vue`, added in the `pages:extend` hook in `nuxt.config.ts` (not a `definePageMeta` alias: Vue Router treats an alias as the same location and drops the EN/ID switch as a redundant navigation), and `composables/useHomeI18n.ts` reads the locale from the path (`/id` → `id`, else `en`) and returns `{ locale, t }`. Every home section calls `useHomeI18n()`; do not pass copy down as props.
- Copy lives in `locales/home/en.ts` (defines the shape, `HomeMessages`) and `locales/home/id.ts` (typed `HomeMessages`, so a missing key fails the type). Interpolated strings are small functions (`localTime(time)`, `thanks(name)`, `whatsappMessage(fields)`).
- PM-editable values sit at the top of each locale file: `budgets` (USD on EN, Rupiah on ID) and `startingPrice` (the line under the services).
- `middleware/home-language.ts` (named middleware on the home page) acts on `/` only: cookie `dh_lang` = `en` stays, `id` → redirect to `/id`; no cookie → first `Accept-Language` tag (server) or `navigator.languages[0]` (client) starting with `id` → save `id` and redirect, else save `en`. `/id` is never redirected. The EN/ID switch in `HomeNav` writes `dh_lang` straight to `document.cookie` on click (so it is set before the middleware runs), so the switch always wins.
- `index.vue` sets `htmlAttrs.lang`, canonical (`https://dimarhanung.dev/` or `/id`), hreflang `en` / `id` / `x-default`, and per-language title, description and `og:locale`. `scrollToTop` in page meta keeps the scroll position when switching EN ↔ ID.
- Other pages are not translated and keep `lang="en"` from `nuxt.config.ts`. Show the EN/ID switch only on translated pages (today: home only). Indonesian copy uses saya/Anda and no em/en dashes (`anti-slop-writing-formal`).

## Key locations

- `pages/(home)/index.vue` — home page composition; the root carries `data-theme` and `data-scheme`, and its head loads only the active theme's fonts and CSS
- `pages/(home)/components/HeroGrid.vue` — hero background. The canvas draws the 24px grid lines itself (same colors as the CSS `#80808029` / `#ffffff1f`, i.e. 16% gray light, 12% white dark; raised from 7% for contrast); the CSS-line div is only first paint and is removed (`canvasReady`) after the first draw. A `MutationObserver` on `<html>` class/style and on the page root's `data-theme` re-reads the theme's `--grid-line`, `--grid-accent`, `--grid-cell` and `--grid-mode` from the grid element. Hover: the cell under the cursor lights in the accent (12% fill, 55% lines), and every cell, including the one under a resting pointer, stays fully on for a random 200–1200ms (`LIT_MIN_MS`/`LIT_MAX_MS`, per cell) and then switches off at once, so an idle pointer leaves plain lines. The user wants random switch-off timing, not a staged sequence (full → half → blink was rejected) and not a smooth fade; fast moves fill in skipped cells. Click: primary `pointerdown` starts a hold, and `pointerup` on `window` (so releasing outside the hero still counts) fires a shockwave from the held cell's center, plus a 45% echo 180ms later. The front grows to 44 cells (≈1056px, so it crosses the whole hero) over 1900ms with an ease-out radius; the front-cell loop is clamped to on-screen cells. `bend(x, y)` moves grid points along the line from each wave's center with a damped swell: `14px * strength * envelope * cos(2π * ahead / 7 cells)`, with the envelope short ahead of the front (0.35 λ) and long behind it (1.2 λ); push scales by `1 - t²` so the bend holds most of the way out. Keep `RIPPLE_PUSH * 2π / RIPPLE_WAVELENGTH` under ~1 (24px was too strong for the user; 14px plain, up to ~25px fully charged) or neighboring lines cross. The user wanted a stronger bend, not brighter color: so lines and lit cells ride the wave; the cells on the front light up, with a sharp leading edge (Gaussian, 1.2 cells) and a tapered lit wake behind it (`exp(3 * ahead / RIPPLE_WAKE)`, 16 cells). Hold: while pressed, `bend` also pulls points toward the pointer, `k = 0.45 * charge * exp(-d²/(5 cells)²)` as a fraction of the distance (keep < 1 or the center folds), with a faint accent glow over the well. Charge eases in over 1000ms and follows the pointer; after release it drops over 220ms. Release strength is `1 + 0.8 * charge`, so a quick click is a plain ripple. `pointercancel` (touch scroll) lets go without a ripple. The wake only lights cells; the line push stays on the front. Front cells draw at `glow * 1.4` (linear fade), capped at the hover style (12% fill, 55% lines). Lines are straight 2-point paths when no wave is live and 6px-sampled polylines while one is. RAF runs only while cells or waves are live. Reduced motion: only the current cell, no trail, no shockwave. No grid under `[data-grid-hole]` elements (the hero text block, the portrait and the proof strip), cut per cell, no soft edge (the user rejected the blurred cutout): every cell touching the element's rect + 8px switches off at once. Cells a moving element leaves stay off for a random 0–260ms (`TRAIL_MS` 130 ± 100%), so with the 240ms blink every cell is back within 500ms of being uncovered (user asked for max 0.5s), then blink 4 hard 60ms steps (step 0 always on, then a stable hash coin flip) before staying on. User asked for max 0.5s after letting go: while a block springs home it carries `data-springing` (set on release, cleared at rest or on re-grab), and cells uncovered by a springing block come straight back with no trail (`lastSpringHidden`), so the whole trail ends within 500ms of release. Hover cells are not lit, and a press does not charge the grid, while the pointer is over a `[data-grid-hole]` element (so clicking a hero button does not fire a ripple). The draggable blocks (`HeroDraggable`) are gone; the `data-springing` trail code is left over from them and inactive. No opacity fades in hide/show: the user wants it to feel retro / Matrix, not smooth. While a returning cell is on during a blink step it draws in the accent (lit cell style, via `blinkingCells`), then settles to plain grid; this applies to any hole that moves or resizes. State is `offCells` and `blinkingCells` (rebuilt each update) plus `cellReturnAt`. The grid is drawn per cell edge; an edge stays while either neighbor cell is on, so the hole keeps a stepped border line. The user wants the trail to be empty grid, not accent-lit cells. Lit cells skip off cells, so nothing lights inside a hole. Resize and theme redraws snap with no trail. `hero-grid-wake` keeps HeroGrid redrawing until 50ms after the last one, so holes follow size changes (SectionHero fires it after a language switch). `CELL` comes from `--grid-cell` (the first-paint CSS lines use the same variable); the ripple and hold sizes are in cells and are recomputed when it changes. `--grid-mode: static` draws lines only (no hover, hold or ripple), `none` draws nothing.

## Home themes

The themes section (`SectionThemes.vue`, above Selected work) restyles the whole home page. It is the PM's proof of using AI with taste, so every theme is judged as a design, not a recolor.

### Files

- `data/home-themes.ts` — registry, in display order: `modern` (default), `brutalist`, `cartoon`, `ancient`, `terminal`, `swiss`, `newspaper`, `retro-os`, `pixel`, `lab`. Per theme: `css`, `fonts`, `fontFaces`, `scheme`, `thumbnail`. Stubs come from `stub(id)` and inherit modern; replace a stub with a full entry when you design it.
- `locales/home/{en,id}.ts` → `themes.items.<id>` (name + one line, shown in the picker and the "Now showing" line) and `themes.extras.<id>` (copy for that theme's slot components; one block per theme, same keys in both files).
- `public/home/themes/<id>.css` — the theme. Plain CSS, served as is (no Tailwind, no build step; native nesting is fine). Self-hosted font files go in `public/home/themes/fonts/<id>/`.
- `public/home/themes/<id>.webp` — 480x300 thumbnail from `scripts/home-theme-thumbnails.mjs`.
- `pages/(home)/components/themes/<id>/<slot>.vue` — optional extra markup (see "Markup variants").
- `pages/(home)/home-theme.css` — the contract: every custom property with modern's values (light, then `.dark .home-page[data-scheme="auto"]`) and the modern rules that use them. `composables/useHomeTheme.ts` — state, cookie, switching. `brutalist.css` is the worked example: read it first.

### How switching works

- Cookie `dh_theme` (1 year). The server renders the saved theme: `data-theme` on the page root and the theme's `<link>`s in the head, so there is no flash of modern. `?theme=<id>` opens that theme and saves it; `home-language` keeps the query through the `/` → `/id` redirect. After a click the address bar shows `?theme=<id>` (removed for modern) so it can be shared.
- Click → `setTheme(id, button)`: loads the theme's stylesheets and slot components, warms `fontFaces` with `document.fonts.load` (max 2s), then swaps inside `document.startViewTransition` (260ms cross-fade). Reduced motion or no View Transitions: instant swap. The clicked button keeps its spot on screen, so a taller hero does not move the page.
- Only the active theme's CSS and fonts load. A stylesheet stays in the head after you switch away; that is harmless because every rule is scoped to its `data-theme`.
- `scheme`: `auto` themes style both modes and keep the dark toggle; `light` / `dark` themes pin one look and the toggle is hidden. The `.dark` contract values only apply to `[data-scheme="auto"]`, so a pinned theme never sees them.

### Writing a theme

1. Research the direction first (real references, the period's actual typefaces, palette and layout habits) and write it down in the header comment of `<id>.css`, like `brutalist.css` does. One committed direction, not a mood board.
2. In `data/home-themes.ts`, replace `stub(id)` with a full entry: `fonts`, `fontFaces`, `scheme`.
3. Set the custom properties on `.home-page[data-theme="<id>"]`, then restyle through the hooks. Scope every rule with that prefix. The file is not in a cascade layer, so it beats the `home` layer and the Tailwind classes in the markup without `!important`, including layout utilities: grid columns, padding, `display`, order. Use your own media queries for responsive changes (your rule wins at every width).
4. Moderate re-layout is fine (a different hero grid, a list instead of cards, a sidebar nav), as long as every section, link and form field still works and reads in a sensible order.
5. Regenerate the thumbnail and check `/` and `/id` at 1440 and 390, with and without reduced motion, and in dark mode if `scheme` is `auto`.

Fonts: a Google Fonts css2 URL in `fonts` (`&display=swap`), or `@font-face` at the top of your CSS pointing at `public/home/themes/fonts/<id>/`. List the faces the first screen uses in `fontFaces` (`'700 1em "Family"'`) so the switch waits for them. Pick real typefaces for the direction (e.g. a period blackletter, a true pixel font, a Helvetica-like grotesk), not a default sans with a new color. Keep it to the weights you use.

Markup variants (escape hatch): prefer CSS (`::before` / `::after` with `content`, `:lang(id)` for per-language decoration text). When a theme needs real extra markup (a masthead, a taskbar, window title bars), add `pages/(home)/components/themes/<id>/<slot>.vue` for one of the slots in `themes/slots.ts`: `page-start`, `hero-start`, `hero-end`, `page-end`. It renders only while the theme is active (server-rendered too) and is downloaded only then. Restart the dev server after adding a new slot file: the server keeps the old file list until then. Copy goes in `themes.extras.<id>`; decorative markup gets `aria-hidden="true"`. If a theme needs a slot somewhere else, add the name to `HOME_THEME_SLOTS` and one `<HomeThemeSlot name="…" />` in the section: keep that change small and mention it.

Thumbnails: start a dev server, then `node scripts/home-theme-thumbnails.mjs --base http://localhost:<port> <id>` (no ids = all). It loads `/?theme=<id>` at 1440x900 with reduced motion, screenshots the first screen and writes a 480x300 webp to `public/home/themes/<id>.webp`. Playwright is found locally, globally (`npm root -g`), or via `PLAYWRIGHT_MODULE=/path/to/playwright`.

Keep working in every theme: focus outlines (`--focus`, visible on the theme's colors), `prefers-reduced-motion` (no transforms on hover, no animation; the photo flip already becomes a fade), the photo toggle's `aria-pressed`, form errors that are not color-only, contrast of body text (4.5:1) and of `--accent-ink` on `--accent`.

### Taste rules (the PM's "AI slop" list applies to every theme)

- No pulsing or status dots, pill badges, tracked-uppercase eyebrows or kickers above headings, "Live" / "New" badges, floating chips, glow orbs or blurred gradient blobs, testimonials, endless or looping motion (`--photo-fx: calm` or `off` if the idle glitch fights the theme).
- Headings still say what the section is. Do not invent copy, numbers or claims; restyle the real content.
- Each theme is a committed, researched direction with real typography and its own layout habits (rules, columns, bevels, grids), not modern with new colors. If two themes could swap palettes and still look right, one of them is not done.
- Color does one job per theme: the accent marks what you can press and the current choice.
- Motion only on hover/press and the switch itself, short and respecting reduced motion.

## Learned user preferences

- Home layout follows the PM-approved "hire-first" mockup (2026-11). Rejected as "AI slop", keep out: pulsing/status dots, availability pill badges, tracked-uppercase eyebrows/kickers above headings, "Live" / "My specialty" badges, tag pills on cards, floating chips, infinite animations, testimonials, glow orbs. Section headings say what the section is. Hover transitions are fine; every motion respects `prefers-reduced-motion`.
- Removed from the home page on purpose: the motto section, the "Challenge Me" cards, the Portofolio / Find Me card grids, the "How I work" philosophy section (`PencilHighlight`), and the draggable hero blocks with `CardParallax`.
- Freelance only: the form's needs are the 3 services plus "Something else"; no full-time/role options or wording.

- The Milky Way stack lives on `/challenges/ui-general`; the starfield notes below apply to `UiGeneralMilkyWayStack.vue`.

- Hero has no blurred gradient orbs or circle glows (read as AI slop). The interactive grid is the hero's background effect.
- Icons always in brand color; no grayscale-until-hover.
- No visible headings inside the tech-stack section; names come only from tooltips. Section carries `aria-label="Tech stack"`.
- Motion must feel smooth: transform/opacity only, ease-out curves, pointer/scroll parallax lerped, no 3D `rotateX/Y` on icon rows (caused hover jitter).
- Space look: an HD Milky Way — cool blue-white band with a warm cream core (bulge, upper right, kept off the icon block), soft dust rift, dense fine star grain, tapered flares on a few near stars. No purple/pink nebula.
- Clouds must look photographic and blended, not like noise shapes. Rejected: smoothstep-thresholded fbm (smoke/marble), band-stretched ridged dust (silk folds). Current model: 3 depth slices, log-normal star clouds `exp(k * fbm)`, dust as Beer-Lambert extinction `exp(-tau * vec3(0.85, 1, 1.18))` (blue dims first, so reddening is automatic), soft `1 - exp(-x)` shoulder. No thresholds.
- Logos on the sky are icon-only (no wordmarks): wordmark text had poor contrast. Flutter: `logos:flutter-icon`, Firebase: `logos:firebase-icon`.
- "Smooth" also means no banding in the dark gradients: the shader dithers its output every frame.
- Starfield sits in a sharp window pane (`.stack-window`): overflow clip, 1.25rem radius (0.75rem on ≤640px), 1px primary-tinted hairline, inset glass lip. No long top/bottom feather. Height lives as `py-[48rem]` on the pane. Width is full (`w-full`, no side gutter).

## Learned Workspace Facts

- `HeroGrid` loops must never step by a size-derived value: a 0×0 canvas (hot reload, page change, hidden hero) once made `drawGrid` step by 0 and froze the tab. `resize` skips 0×0, and straight lines are drawn without a sampling loop.
- Resolved stars (~520) stay on a 2D canvas: depth `d`, DPR capped at 2, RAF loop only while in view; `prefers-reduced-motion` draws one static frame. Glow uses cached radial sprites per stellar tint (`buildGlowSprite(r,g,b)`, 4 tints hot→cool) and a pre-rendered tapered `buildFlareSprite` for the brightest; never `ctx.shadowBlur` or stroked `+` lines.
- Sky is one WebGL canvas, two passes. Pass 1 renders the Milky Way at ≤0.5× CSS px into an RGBA texture (rgb = light, alpha = star density, already dimmed by dust). Pass 2 runs at device px (DPR ≤2, `SKY_PIXEL_BUDGET`), upsamples it, adds procedural star dust (one star per cell anywhere in the cell, 2×2 neighbor lookup — small jitter made a visible lattice), applies the edge well and dithers. While animating, both passes are scissored to the visible rows ± `VISIBLE_PAD`; `preserveDrawingBuffer: true` keeps the rest. The bottom sky color comes from `--app-primary-950`, resolved to sRGB with a 1px canvas and re-read by a `MutationObserver` when the theme switcher rewrites `<html style>`. The CSS gradient + `.stack-well` stay underneath as the no-WebGL fallback and fade-in backdrop.
- One depth camera for everything: depth `d` (1 = first icon row). Drift + pointer shift by `offset / d`; scroll shifts by `scroll * (1 - 1/d)` so far layers hold back and read as farther. Stars live at d 1.4–10, icon rows at `--row-depth` 1 / 1.12 / 1.26, so stars are always behind the icons they pass under. Shader layers: far haze 9, band geometry 6, cloud/dust slices 7 / 5.5 / 4, star dust 7.5 / 4.8.
- The old scroll parallax was inverted (near layers lagged more than far), which flattened depth. Keep far = more hold-back.
- Drift is a slow Lissajous on the camera (no star wrapping jumps); `clock` advances only while the RAF loop runs.
- Pointer and scroll parallax targets are eased in `tick` with `1 - exp(-dt * k)` so damping is frame-rate independent.
- Parallax fan-out: JS sets `--stack-px/--stack-py/--stack-sy` in px on the section; `.stack-icons` applies the same `1/d` and `1 - 1/d` rule from `--row-depth`.
- Headless Playwright defaults to SwiftShader (CPU) WebGL, useless for fps. This machine has an NVIDIA L40S: launch Chromium with `--enable-gpu --use-angle=vulkan --enable-features=Vulkan --disable-vulkan-surface --ignore-gpu-blocklist` to get real GPU numbers (the current sky holds 60 fps there).
- `v-motion-pop-visible` starts at `scale: 0` and resets to it whenever the observer says "not intersecting"; in some headless runs a few icons (often the `:delay="150"` ones) stayed at opacity 0. Intermittent; two runs of the pre-shader version did not show it, root cause unconfirmed. `v-motion-pop-visible-once` is the likely fix if it shows up for real.
- Do not bring back the 24–32rem feather + page-color overlays. The window clip is the edge. Do not add an outer drop shadow (that turns the pane into a card). Do not add side `px-*` gutters on the section.
- Dark logos on the sky: no white `rounded-full` discs (those look like hard stickers). Cursor: `logos:cursor-icon` + `.tech-stack-item-on-dark` (`brightness(0) invert(1)` combined with the drop-shadow; Tailwind `invert` loses to the scoped `filter`). OpenCode: `material-icon-theme:opencode`. Copilot: `selfhst:github-copilot-light`. OpenAI still uses a white disc because the mark is black.
- Deleting a component's `<style>` block while a dev server runs leaves that server broken until it restarts: Nuxt's dev CSS list (`collectDevCss`) keeps every style module the graph ever saw, so the page still links `Foo.vue?vue&type=style&index=0…&lang.css`, Vite serves the raw `.vue` file there, and Tailwind shows `Invalid declaration: \`{{ … }}\`` plus a 404. Restart the dev server; a fresh one is clean. Do not patch around it in Vite: plugin-vue's own transform also fails on the missing block.
- Dev server for this repo runs on port 8089. Hydration warning `class="system"` vs `class="light"` is a pre-existing color-mode mismatch, not from `SectionStack`.
