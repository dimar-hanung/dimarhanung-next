## Key locations

- `pages/(home)/index.vue` — home page composition; page bg is `bg-muted-200 dark:bg-muted-900`
- `pages/(home)/components/HeroGrid.vue` — hero background. The canvas draws the 24px grid lines itself (same colors as the CSS `#80808029` / `#ffffff1f`, i.e. 16% gray light, 12% white dark; raised from 7% for contrast); the CSS-line div is only first paint and is removed (`canvasReady`) after the first draw. A `MutationObserver` on `<html>` class/style re-reads dark mode and `--app-primary-500`. Hover: the cell under the cursor lights in the accent (12% fill, 55% lines), and every cell, including the one under a resting pointer, stays fully on for a random 200–1200ms (`LIT_MIN_MS`/`LIT_MAX_MS`, per cell) and then switches off at once, so an idle pointer leaves plain lines. The user wants random switch-off timing, not a staged sequence (full → half → blink was rejected) and not a smooth fade; fast moves fill in skipped cells. Click: primary `pointerdown` starts a hold, and `pointerup` on `window` (so releasing outside the hero still counts) fires a shockwave from the held cell's center, plus a 45% echo 180ms later. The front grows to 44 cells (≈1056px, so it crosses the whole hero) over 1900ms with an ease-out radius; the front-cell loop is clamped to on-screen cells. `bend(x, y)` moves grid points along the line from each wave's center with a damped swell: `14px * strength * envelope * cos(2π * ahead / 7 cells)`, with the envelope short ahead of the front (0.35 λ) and long behind it (1.2 λ); push scales by `1 - t²` so the bend holds most of the way out. Keep `RIPPLE_PUSH * 2π / RIPPLE_WAVELENGTH` under ~1 (24px was too strong for the user; 14px plain, up to ~25px fully charged) or neighboring lines cross. The user wanted a stronger bend, not brighter color: so lines and lit cells ride the wave; the cells on the front light up, with a sharp leading edge (Gaussian, 1.2 cells) and a tapered lit wake behind it (`exp(3 * ahead / RIPPLE_WAKE)`, 16 cells). Hold: while pressed, `bend` also pulls points toward the pointer, `k = 0.45 * charge * exp(-d²/(5 cells)²)` as a fraction of the distance (keep < 1 or the center folds), with a faint accent glow over the well. Charge eases in over 1000ms and follows the pointer; after release it drops over 220ms. Release strength is `1 + 0.8 * charge`, so a quick click is a plain ripple. `pointercancel` (touch scroll) lets go without a ripple. The wake only lights cells; the line push stays on the front. Front cells draw at `glow * 1.4` (linear fade), capped at the hover style (12% fill, 55% lines). Lines are straight 2-point paths when no wave is live and 6px-sampled polylines while one is. RAF runs only while cells or waves are live. Reduced motion: only the current cell, no trail, no shockwave. No grid under `[data-grid-hole]` elements (the hero text wrapper and the glass card in `CardParallax`), cut per cell, no soft edge (the user rejected the blurred cutout): every cell touching the element's rect + 8px switches off at once. Cells a moving element leaves stay off for a random 0–260ms (`TRAIL_MS` 130 ± 100%), so with the 240ms blink every cell is back within 500ms of being uncovered (user asked for max 0.5s), then blink 4 hard 60ms steps (step 0 always on, then a stable hash coin flip) before staying on. User asked for max 0.5s after letting go: while a block springs home it carries `data-springing` (set on release, cleared at rest or on re-grab), and cells uncovered by a springing block come straight back with no trail (`lastSpringHidden`), so the whole trail ends within 500ms of release. Hover cells are not lit while the pointer is over a `[data-hero-drag]` block: they sat hidden under it and flashed blue once it moved away. No opacity fades in hide/show: the user wants it to feel retro / Matrix, not smooth. While a returning cell is on during a blink step it draws in the accent (lit cell style, via `blinkingCells`), then settles to plain grid; this applies to both draggable blocks. State is `offCells` and `blinkingCells` (rebuilt each update) plus `cellReturnAt`. The grid is drawn per cell edge; an edge stays while either neighbor cell is on, so the hole keeps a stepped border line. The user wants the trail to be empty grid, not accent-lit cells. Lit cells skip off cells, so nothing lights inside a hole. Resize and theme redraws snap with no trail. `hero-grid-wake` keeps HeroGrid redrawing until 50ms after the last one, so holes follow drags. A press inside `[data-hero-drag]` grabs the block instead of charging the grid. `CELL` must match `bg-[size:24px_24px]`.

## Learned user preferences

- The home page stack stays simple and light (no heavy background, no canvas). The Milky Way stack moved to `/challenges/ui-general`; the starfield notes below apply to `UiGeneralMilkyWayStack.vue`.

- Hero has no blurred gradient orbs or circle glows (read as AI slop). The interactive grid is the hero's background effect.
- Icons always in brand color; no grayscale-until-hover.
- No visible headings inside the tech-stack section; names come only from tooltips. Section carries `aria-label="Tech stack"`.
- Motion must feel smooth: transform/opacity only, ease-out curves, pointer/scroll parallax lerped, no 3D `rotateX/Y` on icon rows (caused hover jitter).
- Space look: an HD Milky Way — cool blue-white band with a warm cream core (bulge, upper right, kept off the icon block), soft dust rift, dense fine star grain, tapered flares on a few near stars. No purple/pink nebula.
- Clouds must look photographic and blended, not like noise shapes. Rejected: smoothstep-thresholded fbm (smoke/marble), band-stretched ridged dust (silk folds). Current model: 3 depth slices, log-normal star clouds `exp(k * fbm)`, dust as Beer-Lambert extinction `exp(-tau * vec3(0.85, 1, 1.18))` (blue dims first, so reddening is automatic), soft `1 - exp(-x)` shoulder. No thresholds.
- Logos on the sky are icon-only (no wordmarks): wordmark text had poor contrast. Flutter: `logos:flutter-icon`, Firebase: `logos:firebase-icon`.
- "Smooth" also means no banding in the dark gradients: the shader dithers its output every frame.
- Starfield sits in a sharp window pane (`.stack-window`): overflow clip, 1.25rem radius (0.75rem on ≤640px), 1px primary-tinted hairline, inset glass lip. No long top/bottom feather. Height lives as `py-[48rem]` on the pane. Width is full (`w-full`, no side gutter).

## Learned Workspace Facts

- `HeroGrid` loops must never step by a size-derived value: a 0×0 canvas (hot reload, page change, hidden hero) once made `drawGrid` step by 0 and froze the tab. `resize` skips 0×0, and straight lines are drawn without a sampling loop.
- Resolved stars (~520) stay on a 2D canvas: depth `d`, DPR capped at 2, RAF loop only while in view; `prefers-reduced-motion` draws one static frame. Glow uses cached radial sprites per stellar tint (`buildGlowSprite(r,g,b)`, 4 tints hot→cool) and a pre-rendered tapered `buildFlareSprite` for the brightest; never `ctx.shadowBlur` or stroked `+` lines.
- Sky is one WebGL canvas, two passes. Pass 1 renders the Milky Way at ≤0.5× CSS px into an RGBA texture (rgb = light, alpha = star density, already dimmed by dust). Pass 2 runs at device px (DPR ≤2, `SKY_PIXEL_BUDGET`), upsamples it, adds procedural star dust (one star per cell anywhere in the cell, 2×2 neighbor lookup — small jitter made a visible lattice), applies the edge well and dithers. While animating, both passes are scissored to the visible rows ± `VISIBLE_PAD`; `preserveDrawingBuffer: true` keeps the rest. The bottom sky color comes from `--app-primary-950`, resolved to sRGB with a 1px canvas and re-read by a `MutationObserver` when the theme switcher rewrites `<html style>`. The CSS gradient + `.stack-well` stay underneath as the no-WebGL fallback and fade-in backdrop.
- One depth camera for everything: depth `d` (1 = first icon row). Drift + pointer shift by `offset / d`; scroll shifts by `scroll * (1 - 1/d)` so far layers hold back and read as farther. Stars live at d 1.4–10, icon rows at `--row-depth` 1 / 1.12 / 1.26, so stars are always behind the icons they pass under. Shader layers: far haze 9, band geometry 6, cloud/dust slices 7 / 5.5 / 4, star dust 7.5 / 4.8.
- The old scroll parallax was inverted (near layers lagged more than far), which flattened depth. Keep far = more hold-back.
- Drift is a slow Lissajous on the camera (no star wrapping jumps); `clock` advances only while the RAF loop runs.
- Pointer and scroll parallax targets are eased in `tick` with `1 - exp(-dt * k)` so damping is frame-rate independent.
- Parallax fan-out: JS sets `--stack-px/--stack-py/--stack-sy` in px on the section; `.stack-icons` applies the same `1/d` and `1 - 1/d` rule from `--row-depth`.
- Headless Playwright defaults to SwiftShader (CPU) WebGL, useless for fps. This machine has an NVIDIA L40S: launch Chromium with `--enable-gpu --use-angle=vulkan --enable-features=Vulkan --disable-vulkan-surface --ignore-gpu-blocklist` to get real GPU numbers (the current sky holds 60 fps there).
- `v-motion-pop-visible` starts at `scale: 0` and resets to it whenever the observer says "not intersecting"; in some headless runs a few icons (often the `:delay="150"` ones) stayed at opacity 0. Intermittent; two runs of the pre-shader version did not show it, root cause unconfirmed. `v-motion-pop-visible-once` is the likely fix if it shows up for real.
- Do not bring back the 24–32rem feather + page-color overlays. The window clip is the edge. Do not add an outer drop shadow (that turns the pane into a card). Do not add side `px-*` gutters on the section.
- Dark logos on the sky: no white `rounded-full` discs (those look like hard stickers). Cursor: `logos:cursor-icon` + `.tech-stack-item-on-dark` (`brightness(0) invert(1)` combined with the drop-shadow; Tailwind `invert` loses to the scoped `filter`). OpenCode: `material-icon-theme:opencode`. Copilot: `selfhst:github-copilot-light`. OpenAI still uses a white disc because the mark is black.
- Dev server for this repo runs on port 8089. Hydration warning `class="system"` vs `class="light"` is a pre-existing color-mode mismatch, not from `SectionStack`.
